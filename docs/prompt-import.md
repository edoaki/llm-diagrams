# この図のリポジトリ側のCodexへ貼り付ける指示

添付した `measurements.json` と `measurement-report.md` を使って、このリポジトリの説明用データを実測へ置き換えてください。まず `AGENTS.md`、`docs/real-values.md`、共通データの原本 `components/gpt-representations-not/template.html` を読んでください。

1. 取得レポートとJSONを照合してください。文章は `The capital of France is` と `The capital of France is not`、casesはnotなし・ありの順です。実際のtokenizerのtoken ID・トークン数を使い、図に合わせて単語単位へ戻さないでください。model.numLayers、hiddenSize、componentIndices、位置方式、ブロック出力と最終正規化の区別、候補確率の定義、生成したtokenの接続を確認してください。
2. `node scripts/import-measurements.mjs <measurements.jsonのパス>` で原本へ取り込んでください。形式が異なる場合は、レポートに根拠がある項目だけ変換してください。不足している値を捏造したり、仮置き値を実測扱いにしたりしないでください。取得不能箇所があれば、元のデータを保って必要な情報を報告してください。
3. 共通データはHTML原本内のid=diagram-dataだけを編集し、全図へ同じmodel/casesを反映してください。N-gramの出現頻度表と並べ替えスコアは説明用のまま残し、LLMのsoftmax確率で置き換えないでください。
4. ベクトル・確率と描画用pointsの出所を別々に扱ってください。ベクトル・確率が実測でも、配置が模式的ならprojection.statusをillustrativeのままにしてください。
5. 位置方式がRoPE等なら加算アニメーションが出ないこと、総層数が「第1層 → 第2層 → … → 最終層」へ反映されること、入力と生成後のトークン数が反映されることを確認してください。ブロック番号を見た目の段番号で上書きしないでください。表示しない中間層を1層として説明しないでください。
6. 生の値は丸めず保存してください。数字は表示時だけ小数3桁で切り捨て（負数は0方向）します。確率は0〜1で保存し、画面では％へ変換後に切り捨てます。表記された確率の合計が丸めで100%にならないことを理由に元データを変更しないでください。
7. `npm run build` と `npm test` を実行してください。テストの仮置き値に対する期待が残っていれば、取得データを参照する検証へ変更してください。テストを削除したり、実測値を古い期待値に戻したりしないでください。全7図をHTML単独・オフラインで表示し、幅960・390・320px、not切り替え、位置ベクトル、各表示層、確率表示、N-gramの全場面、生成の再生・停止・リセットを確認してください。長いトークン名や異なる値幅で見切れる場合は配置を調整してください。
8. 変更したファイル、モデルと層数、表示成分、実測に置き換えた範囲、説明用のままの範囲、検証結果を簡潔に報告してください。取得レポートは秘密情報やローカルの不要な絶対パスを含まない形でdocsに保存してください。巨大テンソル・モデル本体はリポジトリに追加しないでください。

この依頼ではGitHubへのpushや公開は行わないでください。データと表示をローカルで完成させてください。
